## 1. Honesty statement (read this first)

| Source | Status | What it is |
|---|---|---|
| ToN_IoT IIoT telemetry (401,119 rows) | **real research data** | UNSW Canberra testbed captures for 7 IoT/IIoT sensors, labelled |
| ToN_IoT Zeek network flows (211,043 rows) | **real research data** | labelled flow records, 44 fields |
| MITRE ATT&CK for ICS text (357 records) | **real public data** | technique, mitigation, malware, group and campaign descriptions |
| Remote-access log (22,686 events) | **synthetic** | generated by `src/s02_generate_context_and_access.py`, seed 3815 |
| Maintenance/incident tickets (320) | **synthetic** | generated by `src/s03_generate_tickets.py` |
| Asset inventory (194) and user directory (114) | **synthetic** | generated by `src/s02` |

Three things that must be said in the report and the oral defence:

1. ToN_IoT is a **research testbed**, not mining equipment. It stands in for mining IIoT
   and OT network behaviour, and the substitution is documented, not hidden.
2. The access log, tickets and asset context are **synthetic**. The four abnormal access
   patterns (password spray, vendor out-of-hours OT access, dormant-account reactivation,
   impossible travel) were **injected deliberately** and recorded in a `gt_scenario`
   column. Detection results therefore mean *"the method found the behaviour we injected"*,
   never *"we found a real attack"*.
3. The ToN_IoT flow mirror used here **has no timestamp column**, so cross-source joins to
   that source are made on IP and asset, not on time. This is recorded as a known
   limitation rather than worked around silently.

## 2. How to run it

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python src/run_all.py            # whole pipeline, raw data -> compliance checklist
python -m pytest tests -q        # 16 test cases
streamlit run app/app.py         # analyst console
jupyter lab notebooks/capstone_walkthrough.ipynb
```

`python src/run_all.py --from s08` resumes at a stage. Every stage also runs on its own
(`python src/s09_anomaly.py`). All runs append to `outputs/logs/run_log.txt`.

**Data acquisition.** The two ToN_IoT files are not redistributed in this repository. Fetch
them once into `data/raw/`:

```bash
git clone --depth 1 https://github.com/PengaloGit/ToN_IoT-datasets.git data/raw/ton_iot_gh
git clone --depth 1 --filter=blob:none --sparse \
    https://github.com/thawatchai2799/SecurityArchitectureSmartCityIoT.git data/raw/netrepo
cd data/raw/netrepo && git sparse-checkout set data && cd -
git clone --depth 1 https://github.com/mitre-attack/attack-stix-data.git /tmp/attack
mkdir -p data/raw/attack_bundle && cp /tmp/attack/ics-attack/ics-attack.json data/raw/attack_bundle/
```

Original source and licence: <https://research.unsw.edu.au/projects/toniot-datasets> (ToN_IoT,
UNSW Canberra) and <https://attack.mitre.org> (MITRE ATT&CK, attribution required).
